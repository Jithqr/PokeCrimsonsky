I want to overhaul the Pokémon tab in the Crimson Sky Marketplace. It should become a Global Daily Rotating Shop.
​Every 24 hours, the app should generate exactly 50 random Pokémon with randomized levels, natures, IVs, and dynamic prices. This pool of 50 Pokémon is shared across all players. If one player buys a specific Pokémon, it becomes 'Sold Out' globally for the rest of the day.
​Please implement this using the following 4-step logic:
​1. Database Updates:
Create a new database table/model called GlobalMarketItem. It needs the following columns:
​id (Primary Key)
​pokemon_species (String/ID)
​level (Integer)
​nature (String)
​ivs (JSON/Dictionary of the 6 stats)
​price (Integer - calculated based on base stat total, level, and IV quality)
​is_sold (Boolean, default: False)
​date_generated (Date)
​2. The 24-Hour 'Lazy Refresh' Logic (Backend):
When the /get_market_pokemon route is called, the backend should do the following:
​Check the date_generated of the items in the GlobalMarketItem table.
​If the date is older than today (or the table is empty): Delete all existing rows. Run a loop 50 times to generate 50 new random Pokémon, calculate a fair price for each, and insert them into the database with today's date.
​If the date is today: Simply query and return the 50 current items.
​3. Purchase Logic & Concurrency (Backend):
Create a /buy_market_pokemon route. When a user tries to buy a Pokémon:
​Query the exact GlobalMarketItem by ID.
​Check if item.is_sold == True: -> Return an error: 'Too slow! Another trainer already bought this Pokémon.'
​Check if the user has enough currency.
​Transaction: Deduct the user's currency, mark the GlobalMarketItem's is_sold to True, and generate this exact Pokémon in the user's personal inventory.
​4. Frontend UI Updates:
​Render the 50 Pokémon returned from the backend.
​If is_sold is False, display the price and allow the item to be clicked/purchased.
​If is_sold is True, gray out the Pokémon card (reduce opacity), change the price tag to a red 'SOLD OUT' badge, and disable the click event."
​Why this approach is best:
​The "Lazy Refresh" prevents you from having to set up complicated Cron jobs on Replit that might fail if your server sleeps. It just checks the date whenever someone opens the shop.
​Concurrency Protection is handled in Step 3. If two players click "Buy" on the exact same Charizard at the same time, the server checks the database first. The first one gets it, and the second one gets the "Too slow!" message.
